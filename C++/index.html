C++

Introduction

C++ is a powerful, general-purpose programming language widely used in systems programming and performance-critical applications. While its syntax can be more complex than languages like Python and may feel challenging for beginners, mastering C++ provides fine-grained control over memory, performance, and hardware-level operations. This control makes it a preferred choice for building operating systems, compilers, and large-scale applications. Notably, open-source projects such as the LLVM compiler infrastructure and many other industry-standard tools are built using C++.

Identifiers

In C/C++, the names of variables, functions, labels and other user defined objects are called identifiers.

  • Identifiers must start with a letter or an underscore
  • Subsequent characters can be number, letter or underscores
  • Identifiers are case-sensitive

There is also a concept of significant characters in an identifier. In C, for external linkage usage, at least first six characters and for internal name, at least first 31 characters are significant in an identifier. In C++, at least the first 1024 characters are significant.

Namespaces

They were introduced to localize the names of identifiers in order to avoid name collisions. namespace keyword is used to declare a namespace.

namespace name {
  // declarations local to this namespace
}

  • A namespace defines a scope by partitioning the global namespace which is unique and limited to the translation unit
  • Scope resolution operator must be used to access the objects defined within a namespace e.g. namespaceName::objectName
  • using keyword can be used to bring the objects declared in a namespace to the current scope starting from the line containing the using statement till end of current scope

using namespace name; // brings all the members of this namespace to the current scope
using name::member; // brings this particular member to the current scope.

  • There may be namespace declarations of same name allowing namespaces to be split over several files or even within the same file
  • A namespace must be declared outside of all other scopes i.e. in global namespace. However, a namespace can be nested in another namespace and one has to qualify the object with all the namespaces that it is contained in using scope resolution operator
  • Standard C++ defines its entire library in its own namespace std
  • If one has large number of references to the members of a namespace then one should bring that namespace to relevant scope. Otherwise, if only certain members are used heavily, then using keyword should be used to bring those individual members into relevant scope
  • Old .h header files put their contents into the global namespace and new style headers put their contents into std namespace

RAII

RAII stands for Resource acquisition is initialization. In RAII, holding a resource is class invariant, and is tied to object lifetime. Resource is allocated during object creation by constructor and resource deallocation is done during object destruction by destructor. It ensures if there is no object leak, then there is also no resource leak.

class FileHandler {
  File* fp;
public:
  FileHandler(string filename) {
    fp = fopen(filename, "w");
    if(!fp) throw std::runtime_error("Failed to open file");
  }

  ~FileHandler() {
    if(fp) fclose(fp);
  }
  FILE* get() const { return fp; }
};
//Above class exhibits RAII principle. Constructor acquires the file and when the object goes out of scope, destructor releases the file. C++ file streams exhibit RAII.

  • RAII only works for resources handled by stack-allocated objects, where there is well defined static lifetime.
  • For RAII to work on heap managed objects, smart pointers should be used.

Smart Pointers

Smart pointers allow automatic memory management, especially for dynamically allocated objects. The standard smart pointer types are defined in the <memory> header file in the std namespace.

Types of Smart Pointers

  • unique_ptr is a smart pointer that provides exclusive ownership of an object. Only one unique_ptr can own an object at a time. When its owning unique_ptr is destroyed or otherwise releases ownership, the object is deleted. A unique_ptr cannot be copied, but ownership can be transferred to another unique_ptr using move semantics.
  • shared_ptr is a smart pointer that allows multiple pointers to share ownership of an object. It uses reference counting to manage ownership and deletes the object when the last owning shared_ptr is destroyed or releases ownership.
  • weak_ptr holds a non-owning reference to an object managed by a shared_ptr. To access the object, it must first be converted to a shared_ptr, typically by calling lock(). A weak_ptr can help break reference cycles formed by shared_ptrs.

smart_ptr<type> name;

Here, smart_ptr and type are placeholders; use a specific type such as std::unique_ptr<T>, std::shared_ptr<T>, or std::weak_ptr<T>.
